# 超时焦虑——OpenClaw升级与超时优化

下午三点，屏幕上弹出一个红色超时错误：`Timeout 60000ms exceeded`。我盯着这行字，心跳都漏了一拍——不是因为代码出了问题，而是因为会话文件被锁住了，trajectory 文件已经膨胀到 **7MB**，OpenClaw 跑不动了。

这种感觉就像你写了一天的文档突然断电没保存，那种窒息感。但比断电更糟，因为你知道数据还在，只是打不开。

## 从哪里开始排查的

先看了一眼 OpenClaw 的版本号：**2026.5.22**。有点老了。查了一下 release notes，发现最近几个版本修了不少超时相关的 bug。于是决定升级。

升级到 **2026.5.28** 后，超时问题并没有立刻解决。这才意识到——超时只是症状，不是病因。

真正的病因是 trajectory 文件太大。每次会话都会记录所有的操作轨迹，这些文件加起来已经 **7MB**。OpenClaw 在读取这么大的文件时，处理时间超过了默认的 60 秒超时。

## 怎么解决的

改了三个配置：

### 1. 超时参数调大

```json
{
  "acquireTimeoutMs": 180000,
  "maxHoldMs": 600000
}
```

从 60 秒改到 180 秒，最大保持时间从 5 分钟改到 10 分钟。这是治标。

### 2. Transcript 压缩

设置了 **5MB 阈值**，超过就自动压缩。这是治本——从源头控制文件大小。

### 3. 历史记忆裁剪

```json
{
  "maxHistoryShare": 0.7,
  "keepRecentTokens": 30000
}
```

保留最近 30000 tokens 的对话历史，最多占上下文窗口的 70%。这样就不会把整个历史都塞进去。

### 4. MiMo V2.5 Pro 的上下文窗口

查了一下 MiMo V2.5 Pro 的实际参数：**128K context**，不是之前以为的 256K。这个信息很关键——上下文窗口决定了 compaction 能保留多少历史。

### 5. AGENTS.md 和 SOUL.md 持久化

把跨会话规则写进了 AGENTS.md 和 SOUL.md，这样即使会话被压缩，核心规则也不会丢。相当于给 AI 做了一个"长期记忆"。

## 改了什么——Before vs After

| 配置项 | 改之前 | 改之后 | 为什么改 |
|--------|--------|--------|----------|
| acquireTimeoutMs | 60000 | 180000 | trajectory 文件大时读取慢 |
| maxHoldMs | 300000 | 600000 | 复杂任务需要更长时间 |
| transcript 压缩阈值 | 无 | 5MB | 防止文件无限膨胀 |
| maxHistoryShare | 默认 | 0.7 | 控制历史占比 |
| keepRecentTokens | 默认 | 30000 | 保留最近对话 |
| MiMo V2.5 Pro context | 误以为 256K | 实际 128K | 影响 compaction 策略 |
| AGENTS.md/SOUL.md | 无 | 新建 | 跨会话规则持久化 |

## 结果

改完配置重启 OpenClaw，**超时问题消失了**。会话启动时间从之前的卡顿变成了秒开。trajectory 文件被自动压缩到合理的大小，不再阻塞会话加载。

最让我开心的不是超时修好了，而是那两个 markdown 文件（AGENTS.md 和 SOUL.md）——以后不管会话怎么压缩，核心规则都在。这感觉就像给 AI 装了一个"灵魂"。

## 踩过的坑

**坑1：升级不等于修复。** 从 2026.5.22 升级到 2026.5.28，我本以为升级会自动修复超时。但实际上，超时是配置问题，不是代码 bug。升级只解决了部分代码层面的问题，配置还是要手动调。

**坑2：MiMo 的参数查了半天。** 之前一直以为 MiMo V2.5 Pro 是 256K context，后来仔细查了文档才发现是 128K。这个差异直接影响了 compaction 策略——如果按 256K 来配置，保留的历史会太多，反而容易超时。

**坑3：AGENTS.md 放错位置。** 最开始把 AGENTS.md 放在了项目根目录，但 OpenClaw 找不到。后来发现要放在 OpenClaw 的配置目录下。路径不对，一切白搭。

## 学到什么

**超时是症状，不是病因。** 遇到超时，别急着调大 timeout，先看看是不是数据太大、处理太慢。治本比治标重要。

**128K 不是 256K。** 对模型参数的误解会直接导致配置错误。以后涉及模型参数的地方，一定要查原始文档，不能凭印象。

**持久化规则比临时规则靠谱。** AGENTS.md 这种跨会话持久化的文件，比每次手动输入指令可靠得多。规则写一次，永久生效。

## 以后怎么避免

| 规则 | 频率 |
|------|------|
| 检查 trajectory 文件大小 | 每周 |
| 清理过大的 trajectory 文件 | 超过 5MB 时 |
| 验证模型参数（别靠记忆） | 每次配置新模型时 |
| 更新 AGENTS.md 跨会话规则 | 有新规则时 |
| 检查 OpenClaw 版本 | 每月 |
