# VPS部署配置——SSH免密+OpenClaw大扫除

昨天后端 API 在本地跑通了，今天要做的事很明确：把股票 App 部署到 VPS 上，让手机也能访问。

听起来简单对吧？`scp` 上传，`npm start`，完事。

结果光 SSH 这一步就折腾了两个小时。不是连不上，是**每次都要输密码**。我后续要反复部署调试，每输一次密码就多一次烦躁。这才下定决心：今天必须把 SSH 免密登录搞定。

## 第一关：SSH 免密登录

VPS 信息：`45.77.175.209`，端口 `8888`（不是默认的 22），用户 `root`。

用的是 ed25519 密钥，比 RSA 更安全也更快。流程其实就三步：

```bash
# 1. 本地生成密钥（如果没有的话）
ssh-keygen -t ed25519

# 2. 把公钥传到服务器
ssh-copy-id -p 8888 root@45.77.175.209

# 3. 验证免密登录
ssh -p 8888 root@45.77.175.209
```

但是——`ssh-copy-id` 这个命令在 Windows 上**不好使**。它是 Linux/Mac 的工具，Windows 的 PowerShell 里没有。

<!-- TODO: 截图：ssh-copy-id 在 PowerShell 报错 -->

手动搞：

```powershell
# 读取本地公钥
$pubKey = Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"

# 通过密码连接，把公钥追加到服务器的 authorized_keys
ssh -p 8888 root@45.77.175.209 "mkdir -p ~/.ssh && echo '$pubKey' >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

搞定。以后 `ssh -p 8888 root@45.77.175.209` 直接连，零密码。那种"一敲回车就连上了"的感觉，比每次输密码爽太多。

## 第二关：部署脚本

免密搞定后，写部署脚本就顺畅多了。

```bash
#!/bin/bash
# stock-app/deploy.sh
cd /var/www/stock-app
git pull origin main
npm install --production
pm2 restart stock-api
```

简单粗暴。用 PM2 做进程管理，崩溃自动重启。股票 App 的 API 跑在 `http://45.77.175.209/stock/`。

部署完第一次访问，浏览器转了半天圈——**404**。

原因：Nginx 没配置 `/stock/` 的反向代理。加了一段 server block：

```nginx
location /stock/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection 'upgrade';
    proxy_set_header Host $host;
    proxy_cache_bypass $http_upgrade;
}
```

重载 Nginx，刷新——**跑通了。** 那一刻的成就感，就像是花了半天组装了一台电脑，按下电源键的那一秒风扇转了。

## 第三关：OpenClaw 性能大扫除

部署的事搞定后，回头处理另一个一直拖着的问题——**OpenClaw 太慢了**。

打开 OpenClaw 的数据目录一看，`~/.openclaw/trajectories/` 下面的轨迹文件已经膨胀到 **7MB+** 一个。Gateway 处理一个请求要 30 秒以上，经常超时。

<!-- TODO: 截图：OpenClaw trajectory 文件大小列表 -->

问题根源：

| 问题 | 原因 | 影响 |
|------|------|------|
| 轨迹文件过大 | 每次对话完整记录，不压缩 | Gateway 加载慢 |
| Gateway 超时 | 默认超时太短 | 请求经常中断 |
| 内存占用高 | 累积数据没有清理 | 整体卡顿 |

解决方案分三步走：

**1. 升级到最新版 2026.5.28**

新版做了很多性能优化，特别是 trajectory 文件的压缩和分段加载。

**2. 增加 Gateway 超时时间**

把默认的 15 秒改到 60 秒。对于复杂任务，15 秒确实不够。

**3. 开启 Compaction 优化**

让 OpenClaw 自动压缩旧的轨迹文件，只保留关键节点。7MB 的文件压缩后只剩 800KB。

处理完重启 Gateway，响应时间从 30 秒降到 **2-3 秒**。这个对比太明显了——就像给一辆堵了很久的车突然清空了前方的路。

## 还发现了一个有趣的事实

翻文档的时候注意到，MiMo V2.5 Pro 宣传说支持 256K 上下文。但实际测试发现，**超过 128K 之后就开始丢信息了**。所以实际可用上下文是 **128K**，不是 256K。

这个发现很重要——如果基于 256K 的假设来设计长对话系统，到 128K 附近就会出莫名其妙的 bug。

## 结果

| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| SSH 连接 | 每次输密码 | 免密直连 | **省 10 秒/次** |
| 股票 App 部署 | 手动操作 5 步 | 一条命令 | **从 10 分钟到 30 秒** |
| OpenClaw Gateway 响应 | 30+ 秒 | 2-3 秒 | **快 10 倍+** |
| Trajectory 文件大小 | 7MB+ | ~800KB | **缩小 90%** |
| MiMo 实际上下文 | 未知 | 128K | 确认了真实上限 |

## 踩过的坑

**坑1：SSH 端口 8888 导致很多默认命令失效。** `ssh-copy-id`、`scp` 默认走 22 端口，每次都得加 `-p 8888`。后来我在 `~/.ssh/config` 里写死了：
```
Host kitlampvps
    HostName 45.77.175.209
    Port 8888
    User root
    IdentityFile ~/.ssh/id_ed25519
```
以后直接 `ssh kitlampvps` 就行，不用记端口号。

**坑2：PM2 的日志默认只保留 5 行。** 调试的时候发现 `pm2 logs` 看不到历史日志。改成 `pm2 logs --lines 100` 才看到完整的错误堆栈。

**坑3：OpenClaw 升级后需要手动清理旧的 trajectory 文件。** 新版兼容旧格式，但旧文件不会自动删除。升级完如果不手动清，还是会加载那些 7MB 的大文件。

## 学到什么

**SSH config 是效率神器。** 一个 `~/.ssh/config` 文件，把 IP、端口、密钥都写死，以后连接就是一行命令的事。早该写，拖到今天才搞。

**部署脚本必须自动化。** 手动操作 5 步和一条命令的区别，不只是速度——是**可重复性**。手动操作每次都可能漏一步，脚本不会。

**第三方工具的宣传数据要打折。** MiMo 说 256K，实际 128K。以后涉及上下文长度的设计，都按宣传值的 50% 来算安全线。

## 以后怎么避免

| 规则 | 频率 |
|------|------|
| 所有 VPS 连接用 SSH config 别名 | 永远 |
| 部署操作必须写脚本，不允许手动 | 每次部署 |
| 第三方上下文长度按宣传值 50% 设计 | 永远 |
| OpenClaw 升级后清理旧 trajectory | 每次升级 |
| PM2 日志行数显式设置 | 每次部署 |
