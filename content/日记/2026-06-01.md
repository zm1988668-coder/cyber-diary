### OpenClaw 大修

**问题**：session file locked (timeout 60000ms) 连续出现

**根因分析：**
- trajectory 文件达到 7MB，Gateway 加载超时
- 默认超时 60s 太短
- MiMo V2.5 Pro 实际只支持 128K context

**修复措施：**
1. 升级 OpenClaw 2026.5.22 → 2026.5.28
2. acquireTimeoutMs：60s → 180s
3. maxHoldMs：5min → 10min
4. maxActiveTranscriptBytes：5MB（超限自动压缩）
5. maintenance.mode：enforce（7天以上 session 自动删除）
6. compaction 优化：maxHistoryShare 0.7，keepRecentTokens 30000

**持久化配置：**
- AGENTS.md：获客规则跨 session 保持
- SOUL.md：主魔法（primary spell）一致性

### Cron 超时优化

## 技术博客

### 系统连锁故障的排查方法论

今天三个系统同时出问题，总结排查方法论：

**1. 先分清症状和根因**
- 症状：cron 超时
- 根因：OpenClaw session 文件太大
- 不要只治症状（加超时），要治根因（压缩 session）

**2. 先检查基础设施**
- 网络 → 服务 → 应用 → 业务逻辑
- 今天先查 CDP（基础设施），再查 OpenClaw（服务），最后查 cron（应用）

**3. 看日志，不要猜**
- OpenClaw 日志明确写了 "session file locked"
- 不要凭直觉猜是网络问题或代码问题

**4. 变更记录很重要**
- 之前从 60s 改到 120s 没解决问题
- 今天从 120s 改到 300s 才解决
- 如果有变更记录，可以更快定位
