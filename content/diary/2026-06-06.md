# npm 告诉我：你有 47 个安全漏洞

打开 KITLAMT 项目，`npm audit` 跑完，屏幕上一行红字：**47 vulnerabilities (3 critical, 12 high)**。

不是今天才有的，一直没管。今天 VPS 上跑了一次 `npm outdated`，发现有几个包已经落后主版本了，不得不正视这个问题。

## 遇到了什么

独立站用的是 Next.js 14，但本地的 `node_modules` 上次装完后就没动过，加上 D 盘有个全局 `npm-cache` 已经占了 **3.2 GB**，每次 install 都要等很久。

问题清单：
1. 47 个安全漏洞，3 个 critical
2. `npm-cache` 在 D 盘，3.2 GB
3. Next.js 依赖里有几个废弃的 peer dep 警告

## 怎么解决的

### 先清缓存

```powershell
npm cache clean --force
# 清理后：D:\npm-cache 从 3.2GB 降到 ~200MB
```

### 升级依赖

```powershell
cd D:\kitlamt-website  # 本地开发版
npm audit fix          # 自动修复可以自动修的
npm audit fix --force  # 强制修复（会升 major 版本，谨慎用）
```

`--force` 之后要测一遍，因为 major 版本升级可能有 breaking change。本地跑了一下 `npm run dev`，页面正常，没有报错。

### VPS 同步

本地测试没问题后，打包推到 VPS：

```bash
ssh root@45.77.175.209 -p 8888
cd /var/www/html
npm install --production
pm2 restart all
```

推完之后访问 kitlamt.com 确认正常。

## 结果

| 指标 | 之前 | 之后 |
|------|------|------|
| 安全漏洞 | 47 个（3 critical） | 6 个（0 critical） |
| npm-cache 大小 | 3.2 GB | ~200 MB |
| install 时间 | ~45s | ~18s |

还有 6 个漏洞是 peer dep 传递进来的，上游还没修，暂时无法修复，不影响生产。

## 踩过的坑

**坑：`npm audit fix --force` 升了 Next.js 大版本，图片组件 API 变了。**
升完 major 版本后，`<Image>` 组件的 `layout` prop 被废弃，控制台报 warning。虽然还能用，但需要改写法：

```jsx
// 旧写法（Next.js 12）
<Image src={img} layout="fill" objectFit="cover" />

// 新写法（Next.js 13+）
<Image src={img} fill style={{ objectFit: 'cover' }} />
```

## 学到什么

**npm 安全漏洞不要拖。** 47 个里面 3 个 critical，这不是小事。养成习惯：每个月跑一次 `npm audit`，别等漏洞多了再处理。

**npm-cache 要定期清。** 浏览器缓存有人知道要清，npm 缓存没人想到——但它同样会无限堆积。设个季度提醒。

## 以后怎么避免

| 规则 | 频率 |
|------|------|
| npm audit 检查 | 每月 |
| npm cache clean | 每季度 |
| 升 major 版本前本地充分测试 | 每次 |
