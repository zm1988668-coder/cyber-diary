# 每次开电脑都要重新登录 FB——这个问题拖了一个月

外贸获客的自动化脚本有个一直没解决的痛点：**每次重启电脑，Chrome 的 CDP 调试模式要重新启动，FB 的登录态有时候会丢失，要手动重新登录。**

一个月来习惯了"忍"，今天决定彻底解决。

## 问题根因

之前的 Chrome 启动方式：

```bat
chrome.exe --remote-debugging-port=9222 --user-data-dir="C:\chrome-debug-profile"
```

问题在于 `user-data-dir` 用的是专门的调试目录，和系统默认的 Chrome 用户数据目录不同。在调试目录里登录的 FB，和日常用的 Chrome 是两套登录态，互不影响。

每次重启如果不用这个 `.bat` 文件启动 Chrome，用的就是普通 Chrome，调试端口没开，脚本连不上。

## 怎么解决的

### 方案：用默认 user-data-dir 启动 CDP

把调试用的 Chrome 改成挂载默认用户数据目录：

```bat
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --remote-debugging-port=9222 ^
  --user-data-dir="C:\Users\Lenovo\AppData\Local\Google\Chrome\User Data" ^
  --profile-directory="Default"
```

这样启动的 Chrome，用的是日常浏览器的登录态，FB、Google、飞书等都保持登录，不需要重新登录。

### 设置开机自启

把这个 `.bat` 添加到 Windows 开机启动：

```powershell
$startupPath = "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup"
Copy-Item "C:\Users\Lenovo\Desktop\Chrome_CDP.bat" $startupPath
```

重启测试：开机后 Chrome 自动启动，CDP 端口 9222 就绪，直接跑脚本不需要任何手动操作。

### 同步更新 Playwright MCP 配置

Playwright MCP 已经替代了之前的 Puppeteer MCP，更新连接配置：

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest", "--cdp-endpoint", "http://localhost:9222"]
    }
  }
}
```

## 结果

| 问题 | 之前 | 现在 |
|------|------|------|
| 开机后是否需要手动操作 | 是（启动 Chrome + 检查登录） | 否（全自动） |
| FB 登录态 | 偶尔丢失 | 与日常浏览器同步，持久有效 |
| 脚本连接成功率 | ~80% | ~99% |

## 踩过的坑

**默认 user-data-dir 被多个 Chrome 实例锁定时会报错。** 日常 Chrome 没关的情况下，再用 CDP 启动一个 Chrome 会提示"用户数据目录已被占用"。解决方法：先关掉普通 Chrome，再运行 CDP 版本。或者用 `--no-first-run` + `--no-default-browser-check` 参数避开提示。

## 学到什么

**CDP 登录态问题的根因是用了独立的 user-data-dir。** 统一成默认目录，问题就消失了。这个方案早该想到，拖了一个月属实不该。
