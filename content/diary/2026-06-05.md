# 脚本不该在桌面活着

早上打开电脑，桌面又多了几个 `.py` 文件。这是前两天赶活留下来的，随手丢在桌面，想着"用完就删"——但从来没有删过。

这个问题不是第一次了。每次赶项目，文件就会像野草一样长在桌面。忍了好久，今天决定顺手整一下，同时把断掉的赛博日记自动化也修回来。

## 遇到了什么

两件事同时压着：

1. **Anta Bot 需要收尾**：安踏平台的自动化机器人，Python 写的，功能跑通了，但日志乱，screenshots 到处飞。
2. **Task Scheduler 停了**：赛博日记的每日自动脚本，6/4 之后没再跑，原因不明。

## 怎么解决的

### Anta Bot 整理

`D:\anta-bot\` 目录下的结构其实还行，问题出在 `logs/` 和 `screenshots/` 没有按日期分目录。每次跑完，文件名就是时间戳，一堆文件堆在一起找不到。

改了一行输出路径：

```python
# 按日期分目录存 screenshots
date_dir = f"screenshots/{datetime.now().strftime('%Y-%m-%d')}"
os.makedirs(date_dir, exist_ok=True)
```

效果立竿见影，跑完之后每天一个文件夹，再也不用翻时间戳了。

### Task Scheduler 诊断

打开任务计划程序看了一下，任务还在，但 **最后运行时间停在 6/4**，状态显示"上次运行结果：0x1"。

0x1 是脚本退出码非零——说明脚本跑了，但中途报错退出了。

查了脚本日志，发现是路径问题：脚本里写的是相对路径 `content/日记/`，但任务计划程序的工作目录不是项目根目录，导致找不到路径。

修复方法：在脚本开头加一行切换目录：

```powershell
Set-Location "C:\Users\Lenovo\Desktop\赛博日记"
```

重新测试，脚本正常跑通，git push 成功。

## 结果

| 项目 | 修复前 | 修复后 |
|------|--------|--------|
| Anta Bot 日志 | 所有文件堆在根目录 | 按日期分目录 |
| Task Scheduler | 0x1 报错，停在6/4 | 正常运行，push 成功 |
| 桌面文件 | 10+ 个临时脚本 | 全部归类到项目目录 |

## 踩过的坑

**坑：Task Scheduler 的工作目录不是脚本所在目录。**
任务计划程序默认的工作目录是 `C:\Windows\System32`，不是你想的项目目录。相对路径全部失效。解决方法：脚本第一行 `Set-Location` 强制跳到正确目录，或者在任务配置里设置"起始于"字段。

## 学到什么

**自动化脚本一定要用绝对路径或者在脚本开头显式切换目录。** 相对路径在本地调试时没问题，因为你是在项目目录下手动跑的；但交给调度器，工作目录就变了。

**"用完就删"是谎言。** 每次都说用完删，但从来不删。以后临时脚本一律放 `tmp/` 目录，不往桌面放。

## 以后怎么避免

| 规则 | 频率 |
|------|------|
| 所有脚本用绝对路径或开头 Set-Location | 每次写脚本 |
| 临时文件放 tmp/，不放桌面 | 每次 |
| Task Scheduler 任务测试时查看"最后运行结果"退出码 | 遇到问题时 |
