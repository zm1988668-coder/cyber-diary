# 工具链升级：Puppeteer 退役，Playwright 上位

今天正式完成了 MCP 的迁移：Puppeteer MCP → Playwright MCP。同时启动了新项目 `haofu-ai-workspace`，把分散在桌面的各种脚本统一收纳。

## Playwright MCP 迁移

### 为什么换

Puppeteer MCP 用了几个月，有几个问题一直没解决：
- 截图 API 和 CDP 连接偶发冲突
- 处理动态渲染页面（React/Vue）时稳定性差
- 官方维护不积极，bug 修复慢

Playwright 的优势：
- 原生支持 CDP 连接已有浏览器
- 更稳定的等待机制（`waitForSelector` 更智能）
- 官方维护，更新快

### 迁移过程

配置文件更新一行搞定：

```json
// 旧配置
"puppeteer": { "command": "node", "args": ["puppeteer-mcp/index.js"] }

// 新配置  
"playwright": { "command": "npx", "args": ["@playwright/mcp@latest", "--cdp-endpoint", "http://localhost:9222"] }
```

测试了 FB 搜索、飞书写入、Google Maps 爬取三个主要场景，全部正常。

## haofu-ai-workspace 项目启动

以前的脚本到处散落——桌面有、`haofu-ai-workbench` 有、`wa-number-extractor` 有——每次找脚本要翻好几个地方。

新建 `D:\haofu-ai-workspace`，统一管理所有自动化脚本：

```
haofu-ai-workspace/
├── login-states/      # Chrome 登录态配置
├── scrapers/          # 各平台爬取脚本
├── feishu/            # 飞书读写工具
├── config.ts          # 统一配置（端口、路径等）
└── 启动调试Chrome.bat  # 一键启动 CDP Chrome
```

把昨天解决的 Chrome CDP 启动脚本也整合进来，重命名为 `启动调试Chrome.bat`，放在项目根目录。

## 踩过的坑

**`@playwright/mcp` 包名会变。** `npx @playwright/mcp@latest` 第一次跑时会下载最新版，但之后如果包更新了 API 会变。建议锁定版本号：`@playwright/mcp@0.x.x`。

## 学到什么

**工具链统一管理比分散放重要。** 以前每个脚本是一个独立文件，配置硬编码在里面。现在统一 `config.ts`，端口改一处，所有脚本都生效。
