# 获客系统优化——Google Maps + Facebook 并行搜索的双引擎

下午三点，盯着飞书表格里那 200 多条半成品客户数据，心里一阵烦躁——有的只有公司名没 WhatsApp，有的有电话但不确定是不是负责人。这就像拼图少了关键几块，每块都有价值，但拼不起来就没法用。

获客这条线，从 5 月 15 号开始搭框架，到现在快两周了。Chrome CDP 端口 18800 一直挂着，登录态完好，但搜索效率一直上不去。根本原因是：**一个一个平台搜，太慢了。**

今天要把这个瓶颈干掉。

## 遇到了什么

核心问题很明确：

1. **Google Maps 搜索和 Facebook 搜索是串行的** —— 搜完 Maps 再搜 FB，一个 10 分钟的活拉到 20 分钟
2. **fb_batch_engine.js 的关键词匹配太死板** —— 只能精确匹配，换个表述就搜不到
3. **分页逻辑有 bug** —— 第二页之后数据就断了

## 怎么解决的

### 第一步：并行搜索架构

把 Google Maps 和 Facebook 改成**并行跑**。一个 Agent 搜 Maps，同时另一个 Agent 用 fb_batch_engine.js 搜 FB。两个平台的结果最后合并去重。

```
之前: Maps(10min) → FB(10min) = 20min
之后: Maps(10min) + FB(10min) = 10min（并行）
```

效率直接翻倍。不是因为技术多复杂，而是**换了个思路** —— 两个平台没有依赖关系，为什么要串行？

### 第二步：fb_batch_engine.js 关键词优化

原来的关键词匹配是硬编码的，改成从关键词库动态提取。搜大众汽配就用 `Volkswagen auto parts`，搜宝马就用 `BMW spare parts`。同时支持模糊匹配，不再死磕精确字符串。

<!-- TODO: 截图：关键词库结构 -->

### 第三步：分页逻辑修复

fb_batch_engine.js 的分页有个经典 bug——翻到第二页后，结果集为空但脚本不报错，静默结束。原因是 Facebook 的滚动加载机制和脚本的 `page.evaluate` 时序冲突。

加了 `MAX_PAGES` 限制和 `waitForSelector` 的超时重试，分页终于稳定了。

## 结果

| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| 单次搜索耗时 | 20 分钟 | 10 分钟 | **-50%** |
| 关键词匹配率 | 精确匹配 | 模糊匹配 | **+30% 覆盖** |
| 分页成功率 | 第二页断掉 | 稳定翻页 | **从 50% → 95%** |
| 单次搜索产出 | 30-40 条 | 60-80 条 | **~2x** |

## 踩过的坑

**坑1：Chrome CDP 端口 18800 假死。** Chrome 进程还在，但 CDP 不响应。不是崩溃，是"装死"。原因是长时间运行后 WebSocket 连接池满了。解决办法：定期检查 `http://127.0.0.1:18800/json/version`，不通就重启 CDP 实例（不用关浏览器，只重启调试端口）。

**坑2：并行搜索时两个 Agent 抢同一个浏览器标签。** Google Maps Agent 和 FB Agent 同时操作 Chrome，结果互相干扰——一个在搜 Maps，另一个把标签切到了 FB。解决办法：严格隔离标签页，一个标签一个平台，Agent 绑定标签 ID。

**坑3：WhatsApp 号码验证的误判。** `whatsapp-bulk-verification` 把一些有效号码标记为无效，原因是网络波动导致验证超时。后来加了重试机制，验证准确率从 85% 提升到 95%。

## 学到什么

**并行不是优化，是重构。** 很多时候"效率低"不是因为单个环节慢，而是串行排列太浪费。两个独立任务并行跑，不需要改任何代码就能提速 50%。

**登录态是最宝贵的资产。** Chrome CDP 的登录态一旦丢失，重新登录 Facebook 需要验证码、手机号确认，流程极其痛苦。宁可多花时间维护 CDP 稳定性，也不要让它崩溃。

**静默失败比报错更可怕。** fb_batch_engine.js 的分页 bug 不是报错，是"安静地结束"。这种 bug 你以为一切正常，直到发现数据少了一半。

## 以后怎么避免

| 规则 | 频率 |
|------|------|
| 检查 CDP 端口连通性 | 每次启动搜索前 |
| 并行 Agent 必须绑定独立标签 ID | 每次并行搜索 |
| WhatsApp 验证必须加重试机制 | 永远 |
| fb_batch_engine.js 更新后先跑 5 条测试 | 每次更新 |
| 搜索结果低于预期时立即排查分页 | 每次搜索 |
