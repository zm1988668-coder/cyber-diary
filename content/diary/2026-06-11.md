# 两件大事同一天撞上了

今天本来计划做 SEO，结果做到一半发现数据库密码可能泄露了——两件事都不能拖，只能同时处理。

## 事件一：MySQL 密码泄露

### 怎么发现的

在看之前的操作记录时，发现有一段 bash 命令包含了 MySQL 密码明文，这段记录出现在了可能被缓存的位置。虽然不确定是否真的被人看到，但"可能泄露"和"已经泄露"的处理方式一样：**立即换。**

### 应急处理流程

```bash
# SSH 登录 VPS
ssh root@45.77.175.209 -p 8888

# 修改 MySQL root 密码
mysql -u root -p
ALTER USER 'root'@'localhost' IDENTIFIED BY 'new_strong_password';
FLUSH PRIVILEGES;

# 修改应用用户密码（kitlamt 用的独立用户）
ALTER USER 'kitlamt_user'@'localhost' IDENTIFIED BY 'another_new_password';
FLUSH PRIVILEGES;
```

同步更新了 `.env` 文件里的数据库连接字符串，重启 Node.js 服务：

```bash
pm2 restart kitlamt-backend
pm2 logs --lines 20  # 确认连接正常
```

**处理时间：约 15 分钟，网站零中断。**

### 以后的规则

从这次事件学到：密码绝对不能出现在命令行历史、日志文件、对话记录里。数据库凭证只放 `.env`，`.env` 加进 `.gitignore`。

## 事件二：SEO Studio 正式上线

### 背景

KITLAMT 独立站上线快一个月了，但 Google 收录情况不理想。用 GSC（Google Search Console）查了一下：**提交了 247 个 URL，只有 89 个被收录（36%）**。

### 做了什么

**1. 安装 `D:\SEO\hf-seo-studio`**

这是专门为 KITLAMT 搭建的 SEO 工作站，包含：
- 关键词分析工具
- 内链结构检查
- 结构化数据生成器（JSON-LD）
- Sitemap 生成和提交

**2. 修复结构化数据**

之前产品页的 JSON-LD 格式有问题，Google 解析不了：

```json
// 修复前（错误）
{
  "@type": "Product",
  "name": "Steering Rack",
  "price": "150"  // 缺少 priceCurrency
}

// 修复后（正确）
{
  "@type": "Product", 
  "name": "Toyota Camry Steering Rack",
  "offers": {
    "@type": "Offer",
    "price": "150.00",
    "priceCurrency": "USD",
    "availability": "https://schema.org/InStock"
  }
}
```

**3. IndexNow 提交**

用 IndexNow 协议把更新过的页面主动推送给搜索引擎：

```bash
curl -X POST "https://api.indexnow.org/indexnow" \
  -H "Content-Type: application/json" \
  -d '{"host":"kitlamt.com","key":"xxx","urlList":["https://kitlamt.com/products/..."]}'
```

一次提交了 **68 个产品页**。

## 结果

| 指标 | 处理前 | 处理后 |
|------|--------|--------|
| MySQL 密码 | 可能泄露 | 已更换，零中断 |
| GSC 收录率 | 36%（89/247） | 待观察（通常2周见效） |
| 结构化数据错误 | 12 个产品页 | 0 |
| IndexNow 提交 | 0 | 68 个页面 |

## 踩过的坑

**坑：PM2 重启后 .env 没有被重新加载。** `pm2 restart` 不会重读 `.env`，要用 `pm2 reload` 或者先 `pm2 stop` 再 `pm2 start`。

**坑：IndexNow 的 key 文件要放在网站根目录。** 没有 key 文件验证，提交会被拒绝。

## 学到什么

**安全事件要立即处理，不要"等一下"。** 今天哪怕 SEO 任务没做完，密码也必须在第一时间换掉。拖一小时，风险就多一小时。

**SEO 不是"发布就完事"。** 结构化数据格式、内链、Sitemap、IndexNow 提交——每一步都影响收录速度。

## 以后怎么避免

| 规则 | 频率 |
|------|------|
| 密码/密钥不出现在命令行和日志 | 永远 |
| .env 加入 .gitignore | 每个新项目创建时 |
| GSC 收录率每周检查 | 每周 |
| 结构化数据用 Google Rich Results Test 验证 | 每次修改后 |
