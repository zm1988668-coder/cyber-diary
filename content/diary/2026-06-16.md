# 网站打不开了，早上7点

早上准备发开发信，顺手打开 kitlamt.com 确认一下——空白页，连接超时。

## 遇到了什么

SSH 进去看，Nginx 进程还在，Node.js 也在，但网站就是不响应。错误日志里一堆 `upstream timed out`。

排查链路：

```bash
# 检查各服务状态
systemctl status nginx     # running ✓
pm2 list                   # online ✓  
systemctl status postgresql # running ✓

# 检查端口
netstat -tlnp | grep 3000  # Node 监听正常

# 检查 PostgreSQL 连接
psql -U kitlamt_user -d kitlamt_db -c "SELECT 1"
# ERROR: too many connections
```

**根因：PostgreSQL 连接数超限。** 默认 `max_connections=100`，Node.js 的连接池没有正确释放连接，跑了几天后连接数耗尽，新请求全部超时。

## 怎么解决的

### 紧急恢复

```bash
# 重启 PostgreSQL 清掉僵尸连接
systemctl restart postgresql
pm2 restart kitlamt-backend
# 网站立即恢复
```

### 根治：限制连接池大小

```javascript
// 修改前：没有设置池大小
const pool = new Pool({ connectionString: process.env.DATABASE_URL });

// 修改后：明确限制
const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  max: 10,        // 最多10个连接
  idleTimeoutMillis: 30000,
  connectionTimeoutMillis: 2000,
});
```

### 顺手做了备份

出了问题才想起来一直没做定期备份。趁这次补上：

```bash
# VPS 上创建每日备份脚本
pg_dump kitlamt_db > /backup/kitlamt-$(date +%Y%m%d).sql
# 备份文件打包到桌面
scp -P 8888 root@45.77.175.209:/backup/kitlamt-20260616.sql .
```

本地保存了一份，命名 `kitlamt-server-backup-20260618-1537`。

## 结果

| 指标 | 故障时 | 修复后 |
|------|--------|--------|
| 网站状态 | 超时不响应 | 正常 |
| PG 连接数 | 100/100（超限） | 稳定在 8-12 |
| 中断时间 | ~2小时（睡觉时发生） | 0 |

## 踩过的坑

连接池不设上限，长期运行必然耗尽。这是教训。

## 学到什么

**数据库连接池必须设上限，不能用默认值。** 生产环境的 `max_connections` 配置要比应用连接池上限高 20%，给 DBA 操作和监控留余量。

**网站必须有监控告警。** 故障发生了 2 小时我才知道，是因为刚好去看。下一步接入 UptimeRobot 免费监控，故障立刻发邮件。
