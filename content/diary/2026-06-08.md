# 3000 条客户数据，但没有 WhatsApp 就等于没有

周末整理了一下这段时间抓下来的 FB 数据。打开飞书表格一数：**3000+ 条记录，其中只有 847 条有 WhatsApp 号码**。

其他的都是公司名、地区、FB 主页链接，没有直接联系方式。这意味着：**超过 70% 的数据用不上**。

## 遇到了什么

外贸获客的核心逻辑是：找到客户 → 拿到 WhatsApp → 发开发信。没有 WhatsApp，流程就断了。

现在的问题：
1. 很多客户 FB 主页上没放 WhatsApp，需要进入主页的"联系方式"标签才能看到
2. 有些客户的 WhatsApp 藏在帖子评论区
3. 飞书表格的列名乱，不同批次抓的数据字段不一致，没法合并分析

## 怎么解决的

### 统一飞书表格结构

重新设计了一个标准列名：

| 列名 | 说明 |
|------|------|
| company_name | 公司/客户名 |
| country | 国家 |
| fb_url | Facebook 主页链接 |
| whatsapp | WhatsApp 号码（带国家码） |
| source | 数据来源（FB/地图/展会） |
| status | 状态（待联系/已发信/有回复） |
| note | 备注 |

把之前 5 个格式不一的表格合并成一张主表，用 Python 做了去重：

```python
import pandas as pd

dfs = [pd.read_excel(f) for f in excel_files]
merged = pd.concat(dfs, ignore_index=True)
merged = merged.drop_duplicates(subset=['fb_url'])  # 以 FB URL 去重
merged.to_excel('leads_master.xlsx', index=False)
```

**合并结果：原来 3,200 条 → 去重后 2,847 条，节省约 11% 重复数据。**

### 优先处理有 WhatsApp 的记录

先把 847 条有 WhatsApp 的筛出来，按国家分组：

| 国家 | 数量 |
|------|------|
| 巴西 | 203 |
| 阿根廷 | 156 |
| 墨西哥 | 134 |
| 南非 | 98 |
| 其他 | 256 |

南美是重点方向，巴西+阿根廷+墨西哥合计 **493 条**，质量不错。

## 踩过的坑

**坑：WhatsApp 号码格式不统一。** 有的是 `+55 11 99999-9999`，有的是 `5511999999999`，有的是 `55 (11) 99999-9999`。合并后一堆格式混在一起，无法直接导入发信工具。

写了一个简单的正则标准化：

```python
import re

def normalize_wa(number):
    # 只保留数字
    digits = re.sub(r'\D', '', str(number))
    # 确保以国家码开头
    if not digits.startswith('55') and len(digits) == 11:
        digits = '55' + digits
    return digits
```

## 学到什么

**没有 WhatsApp 的外贸客户数据，价值只有有 WhatsApp 数据的 20%。** 以后抓取时要把"有没有 WhatsApp"作为核心指标，没有的先不入库，等找到联系方式再录。

**数据标准化要在入库时做，不要等合并时再处理。** 格式统一是最低成本的工作，越早做越省事。

## 以后怎么避免

| 规则 | 执行时机 |
|------|---------|
| 入库前必须标准化 WhatsApp 格式 | 每次导入 |
| 无 WhatsApp 的记录单独存一个"待补全"表 | 持续 |
| 每周统计一次有效联系方式占比 | 每周 |
